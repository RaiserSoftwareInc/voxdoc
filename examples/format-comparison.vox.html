Why Vox? A Format Comparison

Every documentation tool makes trade-offs. Markdown is simple but unstructured. PDF is portable but locked. DOCX is editable but opaque. Plain HTML is flexible but has no semantic layer for tooling. Vox combines the best of each — structured JSON for machines, self-rendering HTML for humans, and enforced accessibility for everyone.

The Structure Problem

⚠️ Markdown
Flat text with formatting hints. No semantic meaning — a heading is just a line starting with #. Tools must guess intent from syntax. No schema, no validation, no guaranteed structure.
💡 {{format_name}}
Every block has a type, unique ID, and validated schema. A heading is a heading block with a level and content. Tools know exactly what they are working with — no guessing.

Accessibility Is Not Optional

Most formats treat accessibility as an afterthought. Authors forget alt text, skip table summaries, and ship inaccessible math. Vox makes this impossible — the compiler rejects documents that fail accessibility checks.

🚨 Compilation fails without these
Every image must have alt text. Every diagram must have a description. Every table must have a summary. Every math block must have spoken text (MathSpeak). No exceptions — the compiler enforces this at build time.
  1. 1
    Author writes a document

    Using the CLI or an AI agent via MCP, the author creates blocks and fills in content. The schema guides what fields are required.

  2. 2
    Compiler checks accessibility

    At compile time, every block is validated against accessibility rules. Missing alt text, empty descriptions, or absent summaries cause a build failure — not a warning.

  3. 3
    Output is WCAG 2.1 AA compliant

    The compiled HTML includes ARIA attributes, skip navigation, semantic elements, and responsive CSS. Screen readers, keyboard navigation, and assistive technology work out of the box.

AI-First Authoring

Vox is designed for AI agents to author documents through the Model Context Protocol (MCP). 24 tools cover the full document lifecycle — from creating blocks to reviewing content to compiling output.

The review model is built into the format. Each block carries a confidence score — high-confidence blocks are auto-approved, uncertain blocks are flagged for human review. When every block passes, the document ships without human intervention.

Self-Rendering: No Tools Required

A .vox.html file is valid HTML. Double-click it, and your browser renders a fully styled document — no CLI, no plugins, no build step. The full Vox JSON source is embedded inside the HTML, so the same file is both human-readable and machine-round-trippable.

Frequently Asked Questions

Why not just use Markdown?

Markdown is great for simple text but has no schema, no block IDs, no accessibility enforcement, and no structured data layer. You cannot programmatically query or modify a Markdown document without parsing ambiguous syntax. Vox gives you structured JSON with typed blocks — tools always know what they are working with.

Can I convert Markdown to Vox?

Yes. The MCP server can assist with converting existing documents by extracting structure, generating block content, and flagging areas that need human review. The conversion process preserves as much semantic meaning as possible and marks low-confidence sections for verification.

Is Vox only for AI-generated content?

No. Vox works equally well for human-authored documents. The CLI provides commands for creating, validating, and compiling documents without any AI involvement. The MCP integration is an option, not a requirement.
